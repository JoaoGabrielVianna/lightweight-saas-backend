# Workspaces

**Scope:** the Workspace domain and the `/v1` API surface it introduced.

A **Workspace** is an isolated administrative context inside one installation.
It will later own a **Connection** to an identity provider — that is the whole
point of the concept — but it owns nothing yet and performs no Keycloak
operation. This document describes what exists.

**Status:** shipped 2026-07-28. Migration `000002_workspaces`, package
[`internal/workspace`](../internal/workspace/), API under `/v1/workspaces`.

---

## 1. What a Workspace is today

| | |
|---|---|
| Persistence | `workspaces` table, created by [000002_workspaces](../internal/database/migrations/000002_workspaces.up.sql) |
| Code | [`internal/workspace`](../internal/workspace/) — model, slug rules, errors, repository, service, handler |
| Identifiers | UUID generated by the application; exposed as `ws_<uuid>` ([`internal/publicid`](../internal/publicid/publicid.go)) |
| API | `/v1/workspaces`, gated exactly as `/admin/*` |
| Relationship to Keycloak | **none** — no Connection, no realm, no admin call |

No workspace is seeded. Migrating the current single-Keycloak configuration
into one belongs with Connection, when there is a real configuration to migrate.

## 2. Public identifiers

Responses always render `ws_<uuid>`. Requests accept either that form or a bare
UUID; the bare form is a development convenience (a value copied out of `psql`
works in `curl` unchanged) and costs nothing in safety, because only a prefixed
id can carry a *wrong* type.

A wrong prefix — `conn_<uuid>` where a workspace was expected — is
`invalid_workspace_id` (400), never `workspace_not_found`. Two reasons: it is a
client bug and should read as one, and a 404 would answer a question about
whether some other object with that UUID exists.

Parsing happens before any query, so a malformed id costs no database round
trip.

## 3. Domain rules

### Slugs

A slug is the stable handle other systems reference. It is **immutable** and
globally unique.

| Rule | |
|---|---|
| Format | lowercase alphanumeric groups joined by single hyphens, ≤ 63 characters (the DNS label limit) |
| Supplied by the client | trimmed and lowercased — **never** slugified. `My Workspace` is an error, not a silent rewrite to `my-workspace` |
| Derived from the name | full slugification, when no slug is supplied |
| Reserved | `admin`, `api`, `system`, `health`, `static`, `docs`, `swagger`, `v1` — refused permanently |
| Released by archiving | **no.** A reference to `production` can never come to mean a different workspace |

The format rule exists twice on purpose: in
[`slug.go`](../internal/workspace/slug.go) and as the
`workspaces_slug_format_check` constraint. The regexes are character-for-
character identical — if you change one, change the other, or a clean 400
becomes a constraint violation surfacing as a 500.

### Lifecycle

```
            create
              │
              ▼
         ┌─────────┐   archive    ┌──────────┐
         │ active  │ ───────────▶ │ archived │ ◀─┐
         └─────────┘              └──────────┘   │ archive (idempotent, no-op)
              │                        │         │
         rename ✓                 rename ✗ ──────┘
                                  reactivate ✗ (not in this slice)
```

- **Archive is idempotent.** Archiving an already-archived workspace succeeds
  and returns it unchanged, so a client retrying after a timeout gets the same
  answer as the original call rather than a spurious conflict.
- **Archive is not a delete.** Nothing is removed and the row stays
  individually readable; only the default listing excludes it.
- **Archived is terminal** in this slice. There is no reactivation path.
- **Only `name` is mutable.** `slug` and `status` sent to `PATCH` are
  *rejected*, not ignored — a client that believes it renamed a slug and got a
  200 would only discover otherwise much later, somewhere else.

## 4. API

All five routes carry the same chain as `/admin/*`, in the same order:

```
RateLimitPerIP → RequireAuth → RequireRole("admin") → RequireLiveAdmin
```

`/v1` is a separate group because it is the product API rather than the
console's admin surface. It is gated identically today because workspace
administration is an operator action; when per-workspace authorization arrives
it will tighten here, never loosen.

| Method | Path | Notes |
|---|---|---|
| `GET` | `/v1/workspaces` | `?status=active\|archived\|all`, default `active`. Ordered by name, then id |
| `POST` | `/v1/workspaces` | `slug` optional — derived from `name` when absent |
| `GET` | `/v1/workspaces/{workspace_id}` | archived workspaces remain readable |
| `PATCH` | `/v1/workspaces/{workspace_id}` | `name` only |
| `POST` | `/v1/workspaces/{workspace_id}/archive` | idempotent |

There is no `DELETE`. Full schemas, parameters and examples are in the
generated OpenAPI spec ([`swagger.yaml`](swagger.yaml)) under the `workspaces`
tag.

### Error envelope

`/v1` uses a stable envelope. The **code** is the contract — statuses collide
(three different things return 400) and messages are prose that will be
reworded.

```json
{
  "error": {
    "code": "workspace_slug_taken",
    "message": "A workspace with this slug already exists",
    "request_id": "3f2504e0-4f89-41d3-9a0c-0305e82c3301"
  }
}
```

| Code | Status | Meaning |
|---|---|---|
| `workspace_not_found` | 404 | No workspace with that id |
| `workspace_slug_taken` | 409 | Slug in use — possibly by an archived workspace |
| `workspace_slug_reserved` | 400 | Platform-reserved slug. 400, not 409: nothing occupies it, the input is simply not acceptable |
| `workspace_slug_invalid` | 400 | Empty, too long, or not in normalized form |
| `workspace_name_required` | 400 | Name absent or blank after trimming |
| `workspace_archived` | 409 | Exists, but archived and therefore not modifiable |
| `invalid_workspace_id` | 400 | Not `ws_<uuid>` or a bare UUID |
| `invalid_status_filter` | 400 | `status` was not `active`/`archived`/`all` |
| `invalid_request` | 400 | Unparseable body, or an immutable field was sent |
| `internal_error` | 500 | Anything unexpected. The cause is logged with the request id and never returned |

**No database detail ever reaches a client.** Constraint names, SQL fragments
and driver messages go to the log, keyed by request id; the client gets
`internal_error`. This is enforced in one place —
`respondError` in [`handler.go`](../internal/workspace/handler.go) — and
asserted by the HTTP tests.

### Request ids

`/v1` responses carry `X-Request-Id`, echoed in the error envelope. A
client-supplied `X-Request-Id` is honoured so a correlation id assigned by a
gateway survives into this API's logs; it is validated first, because the value
lands in both a log line and a response header and is otherwise a
header-injection and log-forging vector. Anything that fails validation is
silently replaced.

The middleware is mounted on the `/v1` group **only**. Mounting it globally
would add the header to every `/admin/*` response, changing a surface that must
stay byte-compatible.

## 5. Invariants, and where each one lives

Application validation is the first line, but it is the line a future bug, a
manual `psql` session, or a second writer can walk around. These invariants are
true of the *data*, not of one code path:

| Invariant | Enforced by |
|---|---|
| `status` ∈ {active, archived} | `workspaces_status_check` |
| `archived_at` set **iff** archived | `workspaces_archived_at_check` (biconditional — an active row with a timestamp is as corrupt as an archived row without one) |
| Slug is in normalized form | `workspaces_slug_format_check` |
| Name is not blank | `workspaces_name_not_blank_check` |
| Slug is globally unique | `idx_workspaces_slug` — the authority under concurrency, which no pre-flight SELECT can be |

Slug collisions reach the application as `gorm.ErrDuplicatedKey` (the
connection is opened with `TranslateError`), so the translation to
`workspace_slug_taken` is deterministic and independent of PostgreSQL's locale
and version. **Nothing branches on a database message string.**

## 6. Layering

```
handler.go     HTTP: binding, status mapping, the error envelope
    ↓
service.go     rules: validation, slug derivation, the archive transition
    ↓
repository.go  persistence — the only file that knows GORM exists
```

`model.go` carries no GORM tags and imports no persistence package. The row
type that talks to the database is unexported in `repository.go` and converts
in both directions, so a schema detail can change without reaching the service,
the handler, or the wire format.
